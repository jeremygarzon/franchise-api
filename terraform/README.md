# Infrastructure as Code (Terraform)

Modular Terraform that provisions the Franchise API on AWS:

```
terraform/
├── bootstrap/            # one-off: creates the S3 bucket for remote state
├── modules/
│   ├── networking/       # VPC, public subnets, Internet Gateway, security groups
│   ├── ecr/              # private Docker image repository
│   ├── secrets/          # Secrets Manager secret for DB credentials
│   ├── rds/              # PostgreSQL instance (not publicly accessible)
│   └── ecs/              # Fargate cluster, task, service, ALB, Auto Scaling, IAM roles
└── environments/
    └── dev/              # composes the modules for the dev environment
```

## Design principles

- **Modular, not monolithic.** Each concern is a reusable module with its own `variables.tf`,
  `main.tf` and `outputs.tf`. Environments only wire modules together and pass values.
- **Remote state.** State lives in an S3 bucket (created by `bootstrap/`) with S3-native
  locking (`use_lockfile = true`), so runs are shared and safe for concurrent access without
  a DynamoDB table. Native S3 locking is GA since Terraform 1.11.
- **No hard-coded secrets.** The database password is generated by Terraform and stored in
  AWS Secrets Manager; ECS reads it at runtime via the task execution role. Nothing sensitive
  is committed or placed in plain-text container environment variables.
- **Least privilege IAM.** The task execution role can pull from ECR and read only the one
  secret it needs; the task role carries no extra permissions.
- **Multi-environment.** `environments/dev` is the template; a `staging`/`prod` folder can
  reuse the same modules with different `*.tfvars` and a different state key.

## Cost note

To stay within a low budget the dev environment runs the Fargate tasks in public subnets
with a public IP (so they reach ECR/CloudWatch through the Internet Gateway) and therefore
does not create a NAT Gateway. The database is still not reachable from the internet: its
security group only allows the ECS tasks, and `publicly_accessible` is `false`. A production
setup would use private subnets with a NAT Gateway.

## Order of operations

```bash
# 1. One-off: create the remote-state backend (uses local state for itself)
cd terraform/bootstrap
terraform init
terraform apply -var "state_bucket_name=<globally-unique-bucket-name>"

# 2. Set that bucket name in environments/dev/backend.tf (bucket = "...") and provision
cd ../environments/dev
terraform init      # connects to the S3 backend created above
terraform plan
terraform apply

# 3. Build and push the image to the ECR repo that Terraform created
ECR_URL=$(terraform output -raw ecr_repository_url)
aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin "${ECR_URL%/*}"
docker build -f ../../../deployment/Dockerfile -t franchise-api ../../..
docker tag franchise-api:latest "$ECR_URL:latest"
docker push "$ECR_URL:latest"

# 4. Force a new ECS deployment to pick up the image
aws ecs update-service \
  --cluster "$(terraform output -raw ecs_cluster_name)" \
  --service "$(terraform output -raw ecs_service_name)" \
  --force-new-deployment
```

The public URL of the service is the `alb_dns_name` output of `environments/dev`.

## Tear down

```bash
# Destroy the environment (ALB, ECS, RDS, VPC, ...)
cd terraform/environments/dev
terraform destroy

# Optional: destroy the state backend as well
cd ../../bootstrap
terraform destroy -var "state_bucket_name=<the-same-bucket-name>"
```
